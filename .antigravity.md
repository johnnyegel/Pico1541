# Project Context: Pico1541
* **Target:** RP2040 (Cortex-M0+)
* **Environment:** `no_std`, `no_main`
* **Domain:** Cycle-accurate Commodore 64 1541 disk drive emulation.

# Architectural Rules: Hardware Abstractions
1. **Static Dispatch:** All hardware interactions (timers, GPIO, serial bus) must be abstracted behind traits. Production code MUST use static dispatch (`<T: Trait>` or `impl Trait`). Do NOT use dynamic dispatch (`&dyn Trait` or `Box<dyn Trait>`).
2. **Zero-Allocation Mocks:** For every hardware trait, a corresponding mock/simulated driver must exist for testing. Both traits and mock drivers must respect `no_std` constraints. If mocks require tracking state history or event queues, use fixed-size arrays (e.g., `heapless` crate) or stack-allocated structures.

# Pico1541 Domain Specifics
When implementing or testing features for this project, adhere strictly to the following hardware realities:
* **Drive Mechanics & Flux:** Track precise drive mechanics. Emulation of disk surface data should expect and handle G64 flux data transitions accurately.
* **VIA Emulation:** The dual 6522 VIA chips handle timing and I/O. Tests involving the VIAs must assert cycle-accurate internal timer states and interrupt flag generation.
* **RP2040 Peripherals:** Abstractions for the IEC serial bus communication and disk head stepping will ultimately map to RP2040 PIO state machines and DMA transfers. Test the logic and state transitions of these abstractions thoroughly on the host before attempting peripheral integration.
* **Bus Accuracy:** Never assume generic timing. Hardware behavior is tied strictly to specific clock lines. Ensure emulation state steps exactly match the underlying hardware bus specifications.

# Testing Protocol (TDD)
1. Read the feature request and identify the required hardware traits.
2. Instantiate the pure software mock drivers on the host.
3. Inject the mocks into the component under test via static dispatch.
4. Execute simulated clock cycles or state transitions.
5. Assert against the internal state of the mock drivers.
6. Refactor implementation until zero regressions occur.
